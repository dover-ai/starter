# DoverAI Starter

Стартовый шаблон production-сервиса на FastAPI. Собран так, как мы отдаём проекты клиентам:
не «работает на демо», а готово к эксплуатации.

Репозиторий одновременно служит **примером Паспорта качества** — набора артефактов,
который [DoverAI](https://doverai.ru) передаёт вместе с каждым проектом.

---

## Что внутри

| | |
|---|---|
| **Стек** | Python 3.12+, FastAPI, SQLAlchemy 2.0, PostgreSQL, Docker |
| **Аутентификация** | JWT, пароли через bcrypt |
| **Тесты** | 30 тестов, покрытие 96% |
| **CI/CD** | GitHub Actions: линтер → тесты → покрытие → сборка образа → проверка запуска |
| **Документация** | архитектура, журнал решений, runbook, чек-лист безопасности, реестр техдолга |

## Быстрый старт

```bash
# 1. Настройки
cp .env.example .env
# сгенерируйте ключ и впишите в SECRET_KEY:
openssl rand -hex 32

# 2. Запуск через Docker (вместе с PostgreSQL)
make up

# 3. Проверка
curl http://localhost:8000/health/ready
```

Документация API: <http://localhost:8000/docs> (в production закрыта).

### Локальная разработка без Docker

```bash
python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
make install
make run
```

### Команды

```bash
make test     # тесты с покрытием
make lint     # линтер
make check    # полная проверка перед коммитом
make cov      # HTML-отчёт о покрытии
```

## Структура

```
app/
  main.py          точка входа, middleware, логи
  config.py        настройки из окружения, проверки безопасности
  db.py            подключение к БД и сессии
  models.py        модели SQLAlchemy
  schemas.py       схемы запросов и ответов
  security.py      хеширование паролей, JWT
  deps.py          общие зависимости FastAPI
  routers/         эндпоинты по доменам
tests/             тесты, включая проверки изоляции данных
docs/              архитектура, решения, эксплуатация, безопасность
```

## Принципы

1. **Секретов в коде нет.** Всё через переменные окружения; в production приложение
   не стартует с ключом-заглушкой.
2. **Схемы отделены от моделей.** Наружу отдаётся только то, что перечислено явно —
   хеш пароля физически не может попасть в ответ.
3. **Владение проверяется в запросе к БД**, а не после выборки. Чужая запись даёт 404,
   а не 403: существование объекта не подтверждается.
4. **Ответы аутентификации неразличимы.** Неверный пароль и несуществующий пользователь
   дают одинаковый ответ — иначе по нему можно перебирать адреса.
5. **Каждый запрос трассируется.** Сквозной `X-Request-ID` и время обработки в логах.
