# Чек-лист безопасности

Проверка перед передачей в эксплуатацию. Отмечено то, что реализовано в шаблоне;
пункты со знаком ⚠ требуют решения на конкретном проекте.

## Секреты и конфигурация

- [x] Секретов нет в коде — все настройки читаются из переменных окружения (`app/config.py`)
- [x] `.env` исключён из репозитория (`.gitignore`)
- [x] В production приложение **не стартует** с ключом-заглушкой
- [x] Длина ключа подписи ≥ 32 байт — требование RFC 7518 §3.2 для HMAC-SHA256
- [x] Правило зафиксировано тестом (`tests/test_config.py`) — его нельзя нарушить незаметно
- [ ] ⚠ Ротация ключа подписи: процедура не автоматизирована

## Аутентификация и пароли

- [x] Пароли хранятся только как bcrypt-хеши с индивидуальной солью
- [x] Сам пароль не сохраняется и не пишется в логи
- [x] Сравнение пароля выполняется в постоянном времени (защита от timing-атак)
- [x] Минимальная длина пароля — 8 символов (валидация схемы)
- [x] Некорректный хеш в БД не роняет приложение
- [ ] ⚠ Требования к сложности пароля минимальны — ужесточить под требования заказчика
- [ ] ⚠ Восстановление пароля не реализовано

## Авторизация и доступ к данным

- [x] Фильтр по владельцу стоит **в запросе к БД**, а не после выборки
- [x] Обращение к чужой записи даёт 404, а не 403 — существование объекта не подтверждается
- [x] Изоляция данных между пользователями закреплена тестами (`tests/test_items.py`)
- [x] Ответ на неверный пароль и на несуществующего пользователя **идентичен** —
      иначе по коду ответа можно перебирать зарегистрированные адреса
- [x] **Время ответа тоже не различается**: для несуществующего адреса проверка пароля
      выполняется против хеша-заглушки (`verify_password_or_equalize`).
      Найдено аудитом 03.09.2026 — было 195 мс против 3 мс, диапазоны не пересекались,
      то есть адрес определялся со стопроцентной надёжностью. Закреплено тестами
      в `tests/test_security_hardening.py`
- [x] Неактивный пользователь не проходит аутентификацию
- [ ] ⚠ Ролевая модель не реализована — добавляется под задачу

## Ввод и вывод данных

- [x] Все входные данные валидируются схемами Pydantic
- [x] Ограничены длины строковых полей — защита от переполнения хранилища
- [x] Параметры пагинации ограничены (`limit` ≤ 100), проверено тестами
- [x] Наружу отдаются только поля, перечисленные в схемах ответа
- [x] Запросы к БД параметризованы через SQLAlchemy — SQL-инъекции исключены

## Транспорт и сеть

- [x] CORS выключен по умолчанию; разрешённые источники задаются явно
- [x] Интерактивная документация и схема OpenAPI закрыты в production
- [x] Заголовки `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy` отдаются всегда;
      `Strict-Transport-Security` и `Content-Security-Policy` — в production
      (в local строгая политика сломала бы интерактивную документацию)
- [ ] ⚠ **HTTPS не настроен на уровне приложения** — терминируется на прокси (nginx, ingress)
- [ ] ⚠ Ограничение частоты запросов (rate limiting) не реализовано — см. реестр техдолга

## Контейнер и развёртывание

- [x] Образ собирается многоэтапно — инструменты сборки не попадают в runtime
- [x] Приложение работает не от root (`appuser`, uid 1000)
- [x] В образ не копируются `.env`, тесты и служебные файлы
- [x] В образе настроен HEALTHCHECK
- [x] Секреты передаются через окружение, а не в слои образа

## Процесс

- [x] CI прогоняет линтер (включая правила безопасности `ruff` набор S) на каждый PR
- [x] Тесты обязательны: сборка падает при покрытии ниже 80%
- [x] Сборка образа проверяется запуском контейнера
- [x] Зависимости проверяются на известные уязвимости (`pip-audit`) — шаг блокирующий
- [x] Секреты ищутся в файлах и **в истории коммитов** (`gitleaks`, полная история)
- [x] Образ сканируется (`trivy`): блокирует HIGH и CRITICAL, для которых есть исправления;
      полная картина, включая неустранимое, выводится в отчёт сборки отдельным шагом
- [x] **Проверено, что защиты срабатывают, а не просто настроены.** 03.09.2026 намеренно
      сломаны: фильтр по владельцу в запросе — упали два теста изоляции; минимальная
      длина ключа — упал тест конфигурации; порог Trivy — шаг завершился с кодом 1
