# 0001. FastAPI и синхронный SQLAlchemy

**Статус:** принято

## Контекст

Нужен шаблон для типовых задач студии: API, интеграции с внешними системами,
боты, отчётность. Проекты чаще всего MVP и внутренние сервисы: важнее скорость
разработки и простота поддержки, чем предельная производительность.

## Варианты

1. **FastAPI + синхронный SQLAlchemy** — простой код, обработчики выполняются в пуле потоков
2. **FastAPI + асинхронный SQLAlchemy** — выше потолок нагрузки, сложнее отладка и тесты
3. **Django REST Framework** — больше «из коробки», но тяжелее и медленнее для API
4. **Flask** — минималистичен, но нет валидации и автодокументации из коробки

## Решение

Вариант 1: FastAPI с синхронным SQLAlchemy 2.0.

## Обоснование

- FastAPI даёт валидацию через Pydantic и OpenAPI-документацию без дополнительной работы —
  один из артефактов паспорта качества генерируется сам
- Синхронный код проще читать, отлаживать и передавать другой команде
- Для нагрузок MVP и внутренних систем разница в производительности незначима:
  FastAPI выполняет синхронные обработчики в пуле потоков
- Асинхронность усложняет тесты и добавляет классы ошибок, которых иначе не было бы

## Последствия

- Потолок производительности ниже, чем у полностью асинхронного стека
- При подтверждённой нагрузке в тысячи запросов в секунду потребуется переход на async;
  границы слоёв это позволяют без переписывания роутеров
- Зафиксировано в реестре техдолга как осознанное ограничение
