# 0002. JWT без хранилища сессий

**Статус:** принято

## Контекст

Нужна аутентификация для API. Клиенты — веб, мобильные приложения, боты.

## Варианты

1. **JWT без хранилища** — сервер не хранит состояние, токен самодостаточен
2. **Сессии в Redis** — можно отозвать в любой момент, но появляется ещё одна зависимость
3. **JWT + чёрный список отозванных** — компромисс, но требует хранилища

## Решение

Вариант 1: JWT (HS256) с коротким временем жизни (60 минут по умолчанию).

## Обоснование

- Нет дополнительной инфраструктуры: на старте проекта Redis — лишний компонент,
  который нужно поднимать, мониторить и восстанавливать
- Горизонтальное масштабирование без общего состояния между экземплярами
- Короткий TTL ограничивает окно, в течение которого украденный токен полезен

## Последствия

- **Токен нельзя отозвать досрочно.** Если он скомпрометирован, остаётся ждать
  истечения TTL либо менять `SECRET_KEY` (что разлогинит всех)
- Смена `SECRET_KEY` — фактически принудительный выход всех пользователей;
  это описано в runbook как известный побочный эффект
- Если появится требование «выйти со всех устройств», решение придётся пересмотреть:
  вариант 3 добавляется без изменения формата токена
