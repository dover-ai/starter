# AGENTS.md — DoverAI Starter

> Единый бриф проекта для ИИ-агентов и разработчиков. Контекст проекта держим в этом файле и в `docs/`,
> чтобы любой агент или человек получил полную картину прямо из репозитория.

## О проекте
Стартовый шаблон production-сервиса на FastAPI — собран так, как мы отдаём проекты клиентам:
не «работает на демо», а готово к эксплуатации. Служит примером Паспорта качества.

## Как запустить
```
cp .env.example .env            # впишите SECRET_KEY: openssl rand -hex 32
make up                         # Docker + PostgreSQL
curl http://localhost:8000/health/ready
```
Локально без Docker:
```
python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
make install
make run
```
Проверки:
```
make test     # pytest с покрытием (порог 80%)
make lint     # ruff
make check    # lint + test, перед коммитом
```

## Стек и конвенции
- **Стек:** Python 3.12+, FastAPI, SQLAlchemy 2.0 (sync), PostgreSQL, JWT (pyjwt), bcrypt, Docker.
- **Линтер:** ruff (line-length 100; наборы E/F/I/B/UP/S). **Тесты:** pytest + покрытие.
- Язык комментариев — русский; в тон окружающему коду.

## Границы (чего НЕ делать)
Инварианты сервиса — их нельзя ломать правками:
- **Секретов в коде нет** — всё через окружение; в production приложение не стартует с ключом-заглушкой.
- **Схемы отделены от моделей** — наружу только то, что перечислено явно (хеш пароля не может попасть в ответ).
- **Владение проверяется в запросе к БД** — чужая запись даёт 404, не 403.
- **Ответы аутентификации неразличимы** — неверный пароль и несуществующий пользователь дают одинаковый ответ.

Общие правила:
- `make check` зелёный перед коммитом.
- Решения и контекст фиксируй **в файлах** (ADR / README), а не только в истории переписки.
